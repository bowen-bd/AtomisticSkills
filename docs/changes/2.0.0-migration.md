# Upgrading from 1.x to 2.0.0

2.0.0 replaces the per-server conda environments with uv projects (three
shared ones plus one pinned project per research stack) and a single launcher,
`venv/run`, and moves the skills to `skills/`. It is not
backward compatible: existing installs, MCP configurations and some model
files need the steps below. Details of the design are in
[2.0.0-uv-runtime.md](2.0.0-uv-runtime.md).

## What breaks

| Area | 1.x | 2.0.0 |
| :--- | :--- | :--- |
| Python environments | ~20 conda envs (`base-agent`, `mace-agent`, …) built by hand | uv projects created on first use: `venv/cpu`, `venv/mlip`, `venv/fairchem`, and `venv/{adit,diffcsp,mattergen,msms,reactot,scd}` for the research stacks |
| Running a skill script | `conda run -n <env> python …`, `# Env:` annotations | `venv/run <env> python …`; SKILL.md commands use `${CLAUDE_SKILL_DIR}/../../venv/run` |
| MCP server configuration | `mcp_config.json` with conda interpreter paths | `venv/run --server <name>`, written by `configure_mcp.py` or the plugin |
| Skill location | `.agents/skills/<name>` | `skills/<name>` (`.agents/skills` remains as a link) |
| SKILL.md metadata | `conda_env` | `metadata.venv` (`conda_env` only for the LAMMPS build of `mat-lammps-md`) |
| Container images | `atomisticskills-lightweight`, `-mace`, `-fairchem`, `-generative` | `atomisticskills-cpu`, `-mlip`, `-fairchem`, `-generative`, built from the uv locks |
| Plugin options | `work_dir` | `runtime`, `image_registry`, `image_tag`; results go to the project directory |
| MatGL | DGL backend | MatGL ≥ 4, PyTorch Geometric only; DGL-based checkpoints do not load |
| Default CHGNet | 2025 MatPES checkpoint | `CHGNet-PES-MatPES-PBE-1M-2026.9`; energies differ, so do not mix them with 1.x results |
| GPU | CUDA 12.x builds | CUDA 13 builds for drivers ≥ 580, CUDA 12.6 builds for drivers 525–579, chosen by `venv/run` |
| DFT input scripts | `generate_inputs.py` submitted to a jobflow-remote project | write the flow to a file; submit only with `--submit --project --worker` |
| Python | 3.10–3.12, per env | 3.12 for the shared projects (NumPy 2); research stacks keep the version they were verified on |
| ICEBERG (`chem-msms-predict`) | ICEBERG 2.0 API, weights placed by hand | ICEBERG 2.1 (ms-pred pinned to a commit); `download_weights.py` fetches the public MassSpecGym weights, and 2.0 checkpoints do not load |
| Upstream checkouts | React-OT, ms-pred and SCD cloned by conda install scripts | React-OT and SCD cloned at pinned commits into `~/.cache/atomisticskills` (see the skills); ms-pred installed as a package |

## Upgrade steps

### Plugin users

```bash
claude plugin marketplace update atomistic-skills
claude plugin update atomistic-skills@atomistic-skills
```

Then restart Claude Code. Environments are created on first use, or ahead of
time with `venv/run --setup` from the plugin directory. The old conda
environments are no longer used.

### Clone users

```bash
git pull
venv/run --setup           # creates venv/cpu, venv/mlip and venv/fairchem
venv/run --doctor          # shows which backend each environment uses
python3 configure_mcp.py   # rewrites the MCP server entries for your agents
```

The research stacks sync on first use, or name them: `venv/run --setup msms scd`.
Remove the 1.x conda environments when nothing else needs them; only the LAMMPS
builds of `mat-lammps-md` still use conda. See
[conda-envs/README.md](../../conda-envs/README.md).

### Your own skills and scripts

- Replace `conda run -n <env> python script.py` with
  `${CLAUDE_SKILL_DIR}/../../venv/run <venv> python ${CLAUDE_SKILL_DIR}/scripts/script.py`,
  and record `metadata.venv: [<venv>]` in the frontmatter.
  `tools/migrate_skill_commands.py` performs this rewrite for the standard
  patterns.
- Write MCP steps as `server.tool`. Without a connected server, run the same
  tool with `venv/run <venv> python -m src.mcp_server.cli <server> <tool> key=value`.
- `src` is importable from any directory: the repository is installed into
  every environment. Remove `sys.path` manipulation added for it.

### Models and results

- Retrain or convert DGL-based MatGL models; MatGL ≥ 4 loads only PyTorch
  Geometric checkpoints. Pretrained names still resolve through the alias
  table, and versioned 2025 names load the weights they name.
- Recompute CHGNet reference energies that results will be compared against.
- FairChem UMA checkpoints are gated on Hugging Face: request access and set
  `HF_TOKEN`.

### Hosts with older NVIDIA drivers

`venv/run` installs the CUDA 12.6 build of torch when the driver is older than
580 and the CUDA 13 build otherwise, in every GPU environment; `venv/run --doctor`
shows which. Drivers older than 525 run models on the CPU, with a warning. The
container images carry the CUDA 13 build only.
