## Engaging findings and fixes (2026-10-05)

| Finding | Fix |
| :--- | :--- |
| uv chose the system `python3.12` (no `python3.12-devel`), so `smol` failed to compile (`Python.h` missing) | `venv/run` builds environments on a uv-managed CPython (`UV_PYTHON_PREFERENCE=only-managed` for syncs, unless set) |
| A managed CPython does not find RHEL's CA bundle, so model downloads failed `CERTIFICATE_VERIFY_FAILED` | `venv/run` sets `SSL_CERT_FILE` to the system bundle on the uv backend when unset (never inside containers) |
| CentOS 7 GPU node (bash 4.2): `venv/run: line 471: extras[@]: unbound variable` | empty arrays expanded with `${a[@]+"${a[@]}"}`; reproduced and verified in a `centos:7` container; test added |
| On glibc 2.17 the launcher blamed the missing compiler | glibc is checked first |
| Apptainer build failed with `DENIED` but suggested `ATOMISTIC_SQUASHFS_PROCS` | an image that cannot be pulled now says so and names the registry/tag settings |
| Driver 550 on an x86_64 GPU node; docs claimed x86_64 used CUDA 12.8 | both architectures use CUDA 13 builds (driver ≥ 580): docs corrected; `--doctor` warns on older drivers. PyTorch publishes cu126 builds of the locked torch versions — a possible option for older-driver clusters, pending a decision |
| FairChem UMA is gated (`401`) | documented (`HF_TOKEN`), and the fairchem server's error now says what to do |
| `python3 tools/...` is Python 3.6 on EL8 | docs use `venv/run cpu python tools/...` |

## Not covered by 1.5.0 testing

- macOS and Windows (unsupported; the launcher refuses with a message).
- The generative stack on x86_64 (conda only; follow-up).
- Hosts with NVIDIA drivers older than 580 cannot use the GPU with the CUDA 13
  builds (confirmed on an Engaging RTX 2080 Ti node, driver 550).
